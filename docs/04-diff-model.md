# 04. 差分モデル (全文表示型 side-by-side)

## 1. 解決する課題

一般的な diff ツールは変更箇所の前後数行のみを出力する。本アプリの要件は「差分表示時もファイル全体を閲覧できる」こと (FR-07) であり、次を同時に満たす必要がある。

- 変更なし行を含めた全行を表示する
- 左右のペインで同じ論理位置が同じ画面行に並ぶ
- 左右のスクロールが 1 つのスクロール位置で同期する

そこで、左右のファイルを **1 本の行ペア列 (`Vec<RowPair>`) へ整列** し、これを唯一のスクロール対象とする。

## 2. データ構造

```rust
/// 1 画面行に対応する左右の対。
pub struct RowPair {
    pub left: Cell,
    pub right: Cell,
    pub kind: RowKind,
}

/// 各側のセル。行番号ではなく行テーブルへの添字を持つ。
pub enum Cell {
    Line(u32),   // LineTable への添字 (0 始まり)
    Pad,         // 対向にのみ行があり、この側は空
}

pub enum RowKind {
    Context,   // 左右同一
    Removed,   // 左のみ (右は Pad)
    Added,     // 右のみ (左は Pad)
    Changed,   // 左右とも存在し、内容が異なる (語単位ハイライト対象)
}

pub struct AlignedDiff {
    pub rows: Vec<RowPair>,
    pub old: LineTable,
    pub new: LineTable,
    pub hunks: Vec<HunkAnchor>,  // ジャンプ用。rows 上の範囲
    pub stat: LineStat,          // +n / -n
}

/// 行の実体はバイト列への範囲で保持し、文字列を複製しない。
pub struct LineTable {
    bytes: Arc<[u8]>,
    ranges: Vec<Range<u32>>,     // 改行を含まない各行の範囲
    trailing_newline: bool,      // 末尾改行の有無
}

pub struct HunkAnchor {
    pub rows: Range<u32>,        // rows 上の変更ブロック範囲
}
```

`RowPair` は 12 バイト程度に収まる。10 万行のファイルでも rows は約 1.2MB であり、全文保持しても問題にならない。

## 3. 整列アルゴリズム

### 3.1 手順

```
入力: old: LineTable, new: LineTable

1. InternedInput::new(old_lines, new_lines) で行を intern
2. Diff::compute(Algorithm::Histogram, &input)
3. diff.postprocess_lines(&input)       // スライダー位置を可読な位置へ寄せる
4. rows = Vec::new()
   old_cur = 0; new_cur = 0
5. for hunk in diff.hunks():             // hunk: { before: Range<u32>, after: Range<u32> }
       // 5-1. 直前の変更なし区間をそのまま出力
       while old_cur < hunk.before.start:
           push RowPair { left: Line(old_cur), right: Line(new_cur), kind: Context }
           old_cur += 1; new_cur += 1
       // 5-2. 変更ブロックを整列
       rows.extend(align_block(&old, &new, hunk.before.clone(), hunk.after.clone()))
       old_cur = hunk.before.end; new_cur = hunk.after.end
6. 残りの変更なし区間を出力 (手順 5-1 と同じ)
```

手順 5-1 の存在が「全文表示」の実体。通常の unified diff がコンテキスト行数で打ち切る箇所を、無制限に出力する。

### 3.2 変更ブロック内の整列 (`align_block`)

ブロックは削除 `d` 行と追加 `a` 行から成る。3 通りに場合分けする。

| 条件 | 出力 |
| --- | --- |
| `a == 0` (純削除) | `d` 行すべてを `Removed` (右は `Pad`) |
| `d == 0` (純追加) | `a` 行すべてを `Added` (左は `Pad`) |
| それ以外 | 下記のペアリングを行う |

**ペアリング規則**

1. 先頭から `min(d, a)` 組を素直に対応付ける (i 番目の削除行と i 番目の追加行)
2. 各組について行類似度 `sim` を計算する
3. `sim >= THRESHOLD` (既定 0.5) なら `Changed` として 1 行にまとめる
4. `sim < THRESHOLD` なら「無関係な行が偶然同じ位置に来た」とみなし、`Removed` 行と `Added` 行に分解して別々の行に出す
5. 余剰行 (`|d - a|` 行) は `Removed` または `Added` として出力し、対向側に `Pad` を入れる

行類似度は語単位差分の結果から求める。

```
sim = 2 * 一致トークン数 / (旧トークン数 + 新トークン数)
```

`align_block` の出力行数は最大 `d + a`、最小 `max(d, a)`。左右の行数は常に一致するため、スクロールは単一の `offset` で足りる。

> 単純な「左右を独立に積む」方式 (常に `d + a` 行) と比べ、ペアリング方式は変更行が左右に並ぶため、1 行内の局所的な変更が読み取りやすい。一方で、ブロックが大きく順序が入れ替わっている場合はペアリングが外れる。

**実装で確定した調整**:

- `THRESHOLD` は 0.35。当初 0.5 を想定したが、短い行が過度に分割されたため下げた
- `d == 1 && a == 1` のブロックは類似度によらず必ずペアにする。1 行が 1 行に置き換わった場合、利用者は「その行の変更」として読むため
- 類似度は語単位差分ではなく、前後に番兵を置いた文字バイグラムの Dice 係数で求める。整列は全行に対して走るため軽量な指標が必要で、語単位差分は `Changed` 行の描画時にのみ遅延計算する。番兵により 1 文字の行でも接頭辞の一致が反映される

### 3.3 語単位差分 (`Changed` 行)

`Changed` 行に対してのみ、描画直前に遅延計算する。

**トークン化**: 次の 3 種の連続を 1 トークンとする。

1. 単語構成文字 (`[A-Za-z0-9_]` および Unicode の文字・数字) の連続
2. 空白の連続
3. それ以外は 1 文字ずつ (記号、CJK 文字を含む)

CJK は単語境界が空白で決まらないため 1 文字単位に落とす。これにより日本語コメントの部分変更も追跡できる。

**計算**: トークン列に対して再度 `InternedInput` + `Diff::compute` を適用し、`is_removed` / `is_added` から強調対象のバイト範囲を得る。

**打ち切り**: 行長が 2000 バイトを超える、またはトークン数が 500 を超える行では語単位差分を行わず、行全体を強調する。長大な 1 行 (minified ファイル等) での計算爆発を防ぐ。

結果は `(row_index)` をキーにキャッシュし、スクロールで再計算しない。

## 4. 行番号

- 表示する行番号は各側の `Cell::Line(i)` に対する `i + 1`
- `Pad` の行では行番号欄を空白にする
- 桁数は `max(old.len(), new.len())` の桁数で固定し、スクロールで幅が揺れないようにする

## 5. 変更箇所ジャンプ

`hunks: Vec<HunkAnchor>` は整列時に構築する。`align_block` を呼んだ範囲の `rows` 上の開始・終了位置をそのまま記録すればよい。

- `]c`: 現在のスクロール位置より後で最初に始まる `HunkAnchor` の先頭へ移動
- `[c`: 現在位置より前で最後に始まる `HunkAnchor` の先頭へ移動
- 移動時はブロック先頭が画面上部から 1/4 の位置に来るようスクロールする

## 6. 折り畳み表示

`z` で折り畳みモードに入ったときは、`rows` を作り直さず **表示行フィルタ** を計算する。

```
keep = 各 HunkAnchor.rows を前後 fold_context 行ずつ拡張した集合の和
gaps = keep に含まれない連続区間
```

`gaps` のうち長さが `fold_context * 2` 未満のものは折り畳まず、そのまま表示する (畳んでも行数が減らないため)。畳む区間は 1 行の区切り行 (`⋯ N lines`) に置き換える。

この設計により、全文表示 ⇄ 折り畳みの切り替えで差分の再計算が不要になり、スクロール位置も `rows` 添字を介して相互変換できる。

## 7. 特殊ケース

| ケース | 扱い |
| --- | --- |
| 新規ファイル / 未追跡 | `old` を空の `LineTable` とし、全行 `Added` |
| 削除ファイル | `new` を空とし、全行 `Removed` |
| リネーム (内容変更なし) | `Context` のみの `AlignedDiff`。ヘッダーに `old_path → path` を表示 |
| リネーム (内容変更あり) | 通常通り整列。ヘッダーに旧パスを併記 |
| 末尾改行の欠落 | `LineTable.trailing_newline` で保持し、欠落側の最終行末に `¬` を表示 |
| CRLF | 行分割時に `\r\n` を 1 つの改行として扱う。行内容から `\r` を除去し、行末に `␍` マーカーを付ける (改行コードのみの差分を可視化するため) |
| タブ | 差分計算はバイト列のまま行い、表示時にのみ空白展開する |
| 超長行 | 折り返しオフ時は表示幅で切り詰め、右端に継続マーカーを出す。語単位差分は §3.3 の打ち切り規則に従う |
| 不正な UTF-8 | 行単位で `from_utf8_lossy` を適用し、置換文字で表示する。差分計算自体はバイト列で行うため結果は正しい |
| バイナリ | 差分計算を行わず `ContentState::Unsupported { Binary }`。判定は先頭 8000 バイト内の NUL バイト有無 (git と同じ規則) |
| サイズ超過 | `max_file_bytes` (既定 2MiB) 超は `Unsupported { TooLarge }` |
| 空ファイル同士 | `rows` 空。「差分なし」を表示 |

## 8. 計算量

| 処理 | 計算量 | 備考 |
| --- | --- | --- |
| 行 intern | O(N) | ハッシュによる重複排除 |
| Histogram 差分 | 実用上ほぼ O(N)、最悪 O(N·D) | `D` は差分サイズ |
| 整列 | O(N) | 行数分の `RowPair` を生成 |
| 語単位差分 | O(可視行のトークン数) | 遅延計算 + キャッシュ |
| 描画 | O(端末高さ) | rows の可視スライスのみ変換 |

支配項は差分計算であり、5000 行のファイルなら数 ms 程度に収まる見込み。NFR-02 (100ms) に対して十分な余裕がある。ただし実測での確認が必要 ([06-implementation-plan.md](06-implementation-plan.md) M2 の受け入れ基準)。

## 9. unified 表示への変換

`u` キーによる unified 表示は `AlignedDiff.rows` から生成する。差分を再計算しない。

```
Context → " " + 左の行
Removed → "-" + 左の行
Added   → "+" + 右の行
Changed → "-" + 左の行、続けて "+" + 右の行 (2 画面行)
Pad     → 出力しない
```

## 10. テスト方針

- **整列のスナップショットテスト**: 入力の旧 / 新テキストと期待される `RowPair` 列を対にした表形式テストを置く。ケース: 純追加、純削除、1 対 1 変更、1 対 3 変更、3 対 1 変更、離れた複数ブロック、先頭変更、末尾変更、末尾改行差のみ
- **不変条件のプロパティテスト**: 任意の 2 テキストについて
  1. `rows` から `Pad` を除いて左側を復元すると `old` と一致する
  2. 同様に右側を復元すると `new` と一致する
  3. `Context` 行の左右の内容は一致する
  4. `hunks` の範囲は互いに重ならず昇順である
- **語単位差分**: トークン化規則ごとのユニットテスト。CJK、絵文字 (結合文字含む)、タブ混在
- **回帰テスト**: 実リポジトリの差分を入力にした整列結果のスナップショット
