## 1. マイルストーン

各マイルストーンは単独で動作する状態を保つ。M2 完了時点で UC-1 (LLM 編集直後のレビュー) が実用できる。

### M0: 骨組み

- Cargo プロジェクト、Rust ツールチェーン固定 (`rust-toolchain.toml`、1.86 以上)
- 端末の raw mode / alternate screen 出入り、RAII ガード、パニックフック
- イベントループ (入力スレッド → 単一 `AppEvent` チャネル → 状態更新 → 描画)
- 空の 2 ペインレイアウト (3:7)、ステータスバー、`q` で終了
- ワーカープールと `TaskRequest` / `TaskResult` の骨組み

**受け入れ基準**: 起動 / 終了で端末が壊れない。パニックさせても端末が復旧する。resize に追従する。

### M1: tree モード

- `ignore` による 1 階層ずつの遅延走査
- `TreeModel` (アリーナ + 可視行の平坦化) と、j/k/g/G/h/l/Enter の操作
- ファイル選択 → 内容読み込み (ワーカー) → 右ペインにプレーン表示
- バイナリ判定、サイズ上限、UTF-8 不正の扱い
- 表示幅計算 (`ui/text.rs`) と全角文字の桁揃え

**受け入れ基準**:
- 1 万ファイル規模のリポジトリで起動からツリー描画まで 300ms 以内 (NFR-01)
- 日本語ファイル名 / 日本語を含むファイル内容で桁揃えが崩れない (NFR-05)
- カーソルキー押しっぱなしで UI が詰まらない (NFR-03)

### M2: diff モード

- `GitBackend` trait と gix 実装 (`discover` / `status` / blob 取得)
- `tree_index` と `index_worktree` の統合規則 ([03](03-architecture.md) §4.1 の表) とそのテーブル駆動テスト
- 変更ファイルの仮想ツリー構築、ステータス記号表示
- 行整列 (`diff/align.rs`) と全文表示型 side-by-side 描画
- 左右スクロール同期、`]c` / `[c` の変更箇所ジャンプ
- 3:3.5:3.5 レイアウト、`m` によるモード切替
- 新規 / 削除 / 未追跡 / リネームの各ケース

**受け入れ基準**:
- 5000 行ファイルの選択から差分描画まで 100ms 以内 (NFR-02)
- [04](04-diff-model.md) §10 の不変条件プロパティテストが通る
- 実リポジトリの差分結果が `git diff HEAD --name-status` と一致する (リネーム検出の閾値差を除く)

### M3: 可読性

- 語単位差分 (`diff/inline.rs`) と遅延計算・キャッシュ
- syntect によるシンタックスハイライト (ワーカー側で全行を一括色付けし、上限行数で保護する)
- 配色テーマ、24bit / 256 色フォールバック、色覚特性への配慮パレット

**受け入れ基準**:
- 10 万行のファイルを開いてもスクロールが 16ms 以内に応答する
- 2000 バイト超の行、minified ファイルでハイライト / 語単位差分が計算爆発しない

### M4: 実用機能

- 折り畳み表示 (`z`) と局所展開
- ファイル内容検索 (`/`, `n`, `N`)、ツリーのファイル名絞り込み (`f`)
- unified 表示トグル (`u`)、行折り返し (`w`)、diff ツリーの並び順 (`S`)
- リロード (`r`)、ペイン幅調整 (`<` / `>`)
- 端末幅による縮退表示

### M5: 仕上げ

- ヘルプオーバーレイ (`?`)
- 設定ファイル (`config.toml`) の読み込み
- CLI 引数 (対象パス、表示オプション)。起動モードは指定させず、常に tree モードで起動して起動後に切り替える
- エラー表示の整理、`Unsupported` と `Failed` の文言
- Nix パッケージ定義 (flake.nix)。`nix build` でテストごとサンドボックス内で検証できる

## 2. テスト戦略

| 層 | 対象 | 方法 |
| --- | --- | --- |
| 単体 | 行整列、語単位差分、表示幅計算、ステータス統合規則 | 表形式のケーステスト |
| プロパティ | 整列の不変条件 ([04](04-diff-model.md) §10) | `proptest` などで任意テキストを生成 |
| 統合 | Git 操作 | 一時ディレクトリに実リポジトリを作って検証。gix でリポジトリを構築し、期待値は `git` コマンドの出力と照合 |
| 描画 | ウィジェットの出力 | ratatui の `TestBackend` でバッファをスナップショット比較 |
| 性能 | NFR-01 / NFR-02 | `tests/perf.rs` に計測を置き、`#[ignore]` で CI から外す |

描画スナップショットは端末幅ごと (80 / 120 / 200 桁) に用意し、縮退表示の回帰を検出する。

### 2.1 性能計測

環境依存のため CI には含めない。手動で走らせる。

```sh
cargo test --release --test perf -- --ignored --nocapture
```

計測は実際のイベントループと同じ経路 (`App::new` → ワーカー結果の処理 → `ui::draw`) を通す。固定条件は 1 万ファイル / 100 ディレクトリ、5000 行 / 変更 50 箇所。

実測 (2026-08-28、Linux 6.18 / release ビルド):

| 項目 | 実測 | 上限 |
| --- | --- | --- |
| NFR-01 起動からツリー描画 | 約 1ms | 300ms |
| NFR-02 選択から差分描画 | 約 2ms | 100ms |
| (参考) 起動から status 反映 | 約 12ms | 要件外 (非同期) |
| (参考) 選択から可視範囲の色付け | 約 23ms | 要件外 (後追い) |
| (参考) 選択から全文の色付け | 約 435ms | 要件外 (後追い) |

ツリーは 1 階層ずつ読むため、ファイル総数はツリー描画時間にほぼ影響しない。1 万ファイルの status 走査も 12ms 程度で、記号の反映を待たされる場面はない。

色付けは当初 `ComputeDiff` と同じタスクで行っており、5000 行の左右 2 面で約 690ms かかって NFR-02 を大きく超えていた (差分計算自体は 1.4ms)。本文表示後の別タスクへ分離し、さらに可視範囲を先に送る 2 段階にした ([05](05-tech-research.md) §5)。

## 3. リスク

| リスク | 影響 | 対応 |
| --- | --- | --- |
| gix の API が版更新で変わる | ビルド不能、修正コスト | バージョン固定 + `GitBackend` trait による隔離。追従は意図的に行う |
| `Repository::status` の使い方が想定と異なる | M2 の見積もり超過 | M2 の最初に最小の検証プログラムを書き、API 形状を確定してから本実装に入る |
| 巨大ファイルでハイライトが遅い | 表示が待たされる | ワーカー側で処理し、上限行数 (既定 20000) を超えるものは色付けしない。結果が届くまでは素のテキストを表示する |
| 行ペアリングの品質が悪い | 差分が読みにくい | しきい値の調整と無効化設定を用意。実リポジトリの差分で目視評価する |
| 全文表示が巨大ファイルでメモリを圧迫 | 動作不安定 | 行実体を複製せず範囲参照で保持する設計 ([04](04-diff-model.md) §2)。サイズ上限で保護する |
| 端末エミュレータ間の描画差異 | 表示崩れ | 主要な端末 (オーケストレータで使うもの) を実機確認。特に全角文字と罫線 |

## 4. 未確定事項

実装着手前に判断が必要な項目。

1. **v1 のスコープ**: 「閲覧専用」で確定してよいか。stage / unstage、`$EDITOR` 連携を含めるか ([01](01-requirements.md) §4)
2. **バイナリ名 / クレート名**: 本ドキュメントでは `tdv` を仮置き
3. **リポジトリ外での起動時の挙動**: tree モードのみで動作させる方針でよいか
4. **staged / unstaged の分離**: v1 では統合表示とするが、LLM がステージまで行う運用なら分離が必要になる可能性がある
