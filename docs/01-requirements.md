# 01. 要件定義

## 1. 背景

MacMini / MacBook からターミナルオーケストレータ経由で Nix PC 3 台を集中監視する運用を行っている。各ホスト上では LLM によるコード編集が走り、変更ファイル数・変更行数が膨大になる。

現状の課題:

- `git diff` のテキスト出力は変更量が多いと追跡困難。ファイル間の位置関係も分からない
- KVM 切り替えで Zed 等の GUI エディタを開くのは手間。作業場所も物理的に限定される
- 監視セッションはターミナルであり、GUI を前提にできない

## 2. 目的

ターミナル内で完結し、以下を満たす閲覧環境を提供する。

- ディレクトリツリーで変更の全体像を把握
- 選択ファイルの差分を左右対比で確認
- 差分だけでなくファイル全体を読める (変更箇所の前後だけに視野が限定されない)

## 3. 対象ユーザー / 実行環境

| 項目 | 内容 |
| --- | --- |
| 実行場所 | 各 Nix PC 上。SSH / オーケストレータのセッション内で起動 |
| 端末 | 真の色 (24bit) 対応前提。非対応時は 256 色へフォールバック |
| 対象リポジトリ | 起動時のカレントディレクトリから探索したローカル Git リポジトリ |
| 表示文字 | 日本語 (全角) を含むファイル名・ファイル内容を正しく桁揃えする |

リモートリポジトリへの直接アクセスは扱わない。「オーケストレータが各ホストのセッションに接続し、そこで本アプリを起動する」構成を前提とする。

## 4. スコープ

### 4.1 v1 に含む

- **tree モード**: ディレクトリツリー + 選択ファイルの内容表示
- **diff モード**: 変更ファイルのツリー + 左右対比の差分表示
- 差分対象は作業ツリー vs HEAD (`git diff HEAD` 相当。staged / unstaged を統合して 1 つの差分として扱う)
- 差分表示時のファイル全文閲覧 (既定で全行展開)
- 変更行への前後ジャンプ
- ファイル名・内容の検索
- シンタックスハイライト
- 未追跡ファイルの表示 (全行追加として扱う)
- バイナリファイル・巨大ファイルの安全な取り扱い (内容展開せず要約表示)

### 4.2 v1 に含まない (v2 以降の候補)

| 項目 | 理由 |
| --- | --- |
| stage / unstage / commit 等の書き込み操作 | 閲覧が主目的。誤操作リスクを排除 |
| staged と unstaged の分離表示 | 合意事項が「作業ツリー vs HEAD」。v2 で切替を追加可能 |
| 任意 ref 間比較 (`HEAD~3..HEAD`, ブランチ間) | v2。データモデルは差し替え可能に設計する ([03](03-architecture.md) 参照) |
| コミット履歴ブラウズ | v2 |
| 外部エディタ (`$EDITOR`) 連携 | 要否未確定 |
| ファイル変更の自動追従 (ファイル監視) | v2。v1 は手動リロード |
| マージコンフリクト解決 | 対象外 |
| SSH 越しのリモートリポジトリ読み取り | 前提構成上不要 |
| サブモジュールの再帰表示 | v1 は 1 エントリとして表示のみ |
| 設定ファイルによるキーマップ上書き (`[keys]`) | 対象外。利用者が単独で、既定のキーで足りる |

> **確認事項**: 4.1 / 4.2 の切り分けは「v1 = 閲覧専用」という仮置きに基づく。stage 操作や `$EDITOR` 連携を v1 に含める場合は本節を改訂する。

## 5. ユースケース

### UC-1: LLM 編集直後のレビュー

1. LLM が編集を終えたホストのセッションで起動 (tree モード)
2. `m` で diff モードへ切り替え、変更ファイル一覧を俯瞰して変更行数の多いファイルを特定
3. 左右対比で差分を確認。周辺のコンテキストが必要なら上下スクロールで全文を読む
4. 次の変更ファイルへ移動、を繰り返す

### UC-2: 変更の妥当性を周辺コードから判断

1. diff モードである関数の変更を発見
2. その関数の呼び出し元が同一ファイル内にあるか、全文スクロールで確認
3. 別ファイルなら tree モードへ切り替えて該当ファイルを開き、内容を読む

### UC-3: リポジトリ構造の把握

1. tree モードでディレクトリ構成を確認
2. `.gitignore` 対象は既定で非表示。トグルで表示

## 6. 機能要件

| ID | 要件 |
| --- | --- |
| FR-01 | 起動時にカレントディレクトリから上位へ Git リポジトリを探索する。見つからない場合は tree モードのみで動作する |
| FR-02 | 起動時は常に tree モードとし、起動後に tree / diff をキー 1 つで相互に切り替える。起動オプションでモードを指定させない |
| FR-03 | tree モードのツリーは実ファイルシステムを反映し、ディレクトリを遅延展開する |
| FR-04 | diff モードのツリーは変更のあるファイルのみで構成する |
| FR-05 | ツリーの各エントリに Git ステータス記号 (追加 / 変更 / 削除 / 未追跡 / リネーム) を表示する |
| FR-06 | diff は左に旧内容 (HEAD)、右に新内容 (作業ツリー) を配置し、行を対応付けて表示する |
| FR-07 | 差分表示は既定でファイル全行を表示する。折り畳み表示へのトグルを提供する |
| FR-08 | 変更行内の語単位の差異を強調表示する |
| FR-09 | 左右ペインのスクロールは同期する |
| FR-10 | 次 / 前の変更箇所へジャンプできる |
| FR-11 | リロード操作で Git 状態とファイル内容を再取得する |
| FR-12 | ツリー内のファイル名検索、および表示中ファイル内容の検索ができる |
| FR-13 | バイナリファイルは内容を展開せず、その旨とサイズを表示する |
| FR-14 | しきい値を超える巨大ファイルは差分計算を行わず、その旨を表示する |

## 7. 非機能要件

| ID | 要件 | 目標値 |
| --- | --- | --- |
| NFR-01 | 起動からツリー描画までの時間 | 1 万ファイル規模のリポジトリで 300ms 以内 |
| NFR-02 | ファイル選択から差分描画までの時間 | 5000 行ファイルで 100ms 以内 |
| NFR-03 | キー入力への応答 | 常に 16ms 以内に再描画。重い処理で UI をブロックしない |
| NFR-04 | メモリ使用量 | 開いているファイル数に比例。全ファイルを事前ロードしない |
| NFR-05 | 文字幅 | 全角文字を含む行の桁揃えが崩れない |
| NFR-06 | 依存 | C ツールチェーン依存を避け、`cargo build` のみでビルド可能にする |

NFR-06 は Nix 環境での再現ビルドを容易にするための方針。Git 実装に pure Rust の gix を選ぶ根拠でもある ([05-tech-research.md](05-tech-research.md) 参照)。

## 8. 制約

- 実装言語は Rust
- 端末の最小サイズは 80x24。それ未満では機能を段階的に縮退させる (左ペイン非表示 → 単一ペイン)
- 端末の resize に追従する
